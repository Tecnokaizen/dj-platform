# Operational Runbooks

## Purpose

Runbooks document repeatable operational procedures.

They reduce uncertainty during routine work and incidents.

---

# Philosophy

If an operation is repeated, it should be documented.

Knowledge should never depend on memory.

---

# Typical Runbooks

Examples:

- Deploy Platform
- Restore Database
- Rotate Secrets
- Upgrade Dependencies
- Scale Infrastructure
- Recover Storage
- Renew Certificates

---

# Structure

Every runbook should include:

- Purpose
- Preconditions
- Procedure
- Verification
- Rollback
- References

---

# Documentation

Runbooks should remain current.

Outdated runbooks should be updated immediately after use.

---

# AI Development Rules

AI coding agents should follow runbooks rather than invent operational procedures.

---

# Final Principle

Runbooks transform experience into repeatable knowledge.
